# SixLine v0.2 workflow implementation report

Verified on 2026-10-07 against the real Linux Electron application. Package metadata is now 0.2.0. The existing document, import/export, engraving and SoundFont playback architecture remains in place.

## Selection architecture

`src/editor/selection.ts` defines a track-scoped, inclusive anchor/focus range with beat or measure granularity and optional string/MIDI-pitch restrictions. The selection is editor state, independent of the song and player. Undo entries retain caret and selection snapshots. Beat navigation extends across existing bars without creating content; measure selection includes the full measure, including implicit silence. Plain horizontal arrows collapse a selection toward the corresponding edge.

Shift+Left/Right extends by beat; Ctrl+Shift+Left/Right extends by measure. Shift-click extends the range, Ctrl-click toggles note rows, Ctrl+A selects all measures, and Escape clears the selection. The Edit menu selects single beats/chords, individual rows and measures. Transparent score overlays show ranges; note restrictions highlight individual note heads. Guitar, bass, drums and keys use the same selection model.

## Copy, cut and paste

Ctrl+C/X/V use a clipboard within the running SixLine window, including across document tabs. No-selection copy/cut addresses the caret beat. Beat selections copy the primary voice; whole-measure selections copy every voice. Structured cloning retains note/beat fields, including velocities, effects, tuplets, rests, grace notes and tremolo. Internal ties survive, including across sparse chords; ties with external or removed origins become ordinary attacks.

Cut replaces notes with rests without shifting musical time. Paste overwrites time beginning at the caret and extends the shared bar structure and all tracks together. Exact rest padding supports straight and triplet rhythms. One ordinary voice can paste from a mid-measure caret; multiple voices require a measure boundary. Whole-measure boundary paste requires matching meters. Same-type track paste is supported; stringed tracks also require matching tuning and capo. Unsupported conversions and placements that would split notes or pasted beats are rejected with a clear status message before mutation. Paste/cut and all resulting extension are one undo operation.

## Duplicate

Ctrl+D and the Edit menu duplicate the selection immediately after itself. Without a selection they duplicate the current measure. Whole-measure duplication inserts shared bars, copies the selected track's complete measures, and inserts empty measures on other tracks. Meter, markers and tempo changes follow the inserted measures; the original starting tempo is restored if the source section changes tempo internally. Beat duplication inserts the primary-voice passage and reflows subsequent beats without silently splitting notes. Duplication is one undo operation.

## Playback from caret and looping

Space retains play/pause behavior at the current playback position. Ctrl+Space, Play Here and the Playback menu start at the caret or selection start. AlphaTab's repeat-expanded tick lookup supplies the musical time shared by all tracks, including tempo changes. Editing selection/caret does not seek the player.

Loop Selection snapshots musical boundaries. A/B points are independent of selection; A is inclusive and B is exclusive. Both use AlphaTab's same playback-range and looping controls, with a visible active-loop button, saved-range toggle and clear command. A range that traverses a repeat into unselected bars is rejected. The MIDI generator gates events at the exact end tick. Audio-buffer position overshoot is bounded to the musical loop edge before it reaches the playhead and event consumers; E2E separately verifies actual note events stay within the range.

## Practice speed, metronome and count-in

The compact practice row supports arbitrary 25–200% speed, including all requested presets. The native synth multiplier preserves pitch and musical tick position without rewriting MIDI or changing the document. Live speed changes retain the playing state.

The metronome uses short WebAudio oscillator clicks, with a higher/louder accent at each bar start. A short lookahead follows the player's repeat-expanded ticks, tempo changes, meter and speed, including loop boundaries. Pauses/seeks cancel queued clicks; metronome toggling does not regenerate the player. Count-in supports off, one and two bars, using the actual start position's meter and tempo and the current speed. Space/Stop cancels it; speed changes during count-in affect its remaining progress. Count-in precedes playback/resumption and the initial loop start, rather than every loop iteration. Practice settings are per open document tab, ephemeral and absent from the song/exported MIDI.

## Markers and navigation

Optional `MasterBar.marker` stores one rehearsal label at a measure boundary, retaining native project version 1 compatibility. Add/rename/delete, direct dropdown jumps, next/previous marker, Go to Measure (Ctrl+G), previous/next measure and beginning/end of song are implemented. Labels appear above the score and follow structural edits. GP sections map to labels on import. MIDI marker import is deferred.

## Playback continuity audit

| Action | Player handling |
| --- | --- |
| Track switch | Render the same Score; retain player, tick, state and scroll where practical |
| Caret, selection, drum-row or keys-pitch navigation | Cursor/view events only; no MIDI regeneration or seek |
| Non-destructive dialogs/menus | No player action |
| Marker or track-name edit | Update engraving on the same Score; no audio invalidation |
| Notes, rhythm, meter, tempo, track sound/mix or structure changes | Regenerate playback; restore captured tick and playing/paused state |
| Document-tab switch | Intentionally stop the old document's playback |
| Explicit stop/pause/seek/play-from-caret/loop commands | Change playback as requested |

Playback restoration subscribes to the public player-ready event to avoid AlphaTab 1.8's recursive worker `loadedMidiInfo` getter. No import/export subsystem was rewritten.

## Remaining limits and next usability work

The clipboard is internal to one running window. Partial beat operations require representable boundaries; automatic note splitting and effect-aware tied continuation across new bar lines are not implemented. Grace notes and multiple voices use whole-measure operations. Loop points remain tick snapshots rather than following later structural edits. Count-in uses a renderer timer and is not sample-accurate. Practice settings are not saved across application restarts. Existing alphaTab playback/export velocity quantization remains unchanged.

The highest-value follow-ups are faithful tied splitting for more flexible beat paste/duplication, clearer start/end-of-measure A/B commands, and saving practice preferences. These should precede unrelated feature work.
